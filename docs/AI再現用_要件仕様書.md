## 1. プロダクト概要

### 1.1 コンセプト

**「今日やることを簡単に管理し、あとから自分が何をしたか振り返れる」** ための、軽量・シンプルな**個人用**タスク管理アプリ。チーム共有・権限・コメント・添付といった重量機能は持たない。

同一のタスクデータを **2つの視点** で扱える点が本アプリの中核設計である：

- **コンソール視点** … 「Today（今日）」＋「Calendar（カレンダー）」。日々の実行に集中する。
- **WBS視点** … プロジェクトを親子ツリーに分解し、ガントチャートで計画・進捗を俯瞰する。

データモデルは1つ。ビューは「見せ方」の違いにすぎない。

### 1.2 最重要の設計思想

1. **入力を速くする** … タスク管理自体を作業にしない。タイトル入力＋Enterで即登録。
2. **今日に集中する** … 通常利用はコンソール（Today）だけで完結する。
3. **予定と実績を分離する** … 「いつやる予定か（`scheduled_date`）」と「実際にいつ完了したか（`completed_at`）」を別管理する。
4. **完了履歴を資産にする** … 完了タスクは削除せず「自分が何をしたか」として蓄積する。
5. **月次振り返りを簡単にする** … 1クリックで「今月やったこと」をコピー／レポート出力できる。
6. **オフラインファースト＆依存最小** … 全データはローカルに保存。外部通信は自動更新チェックのみ。

### 1.3 対象ユーザー・用途

個人利用のみ。日々のTodo／仕事／個人開発／勉強／投資・調査／生活タスク／月次振り返り。チーム利用は対象外。

## 2. 技術要件

### 2.1 推奨スタック（「同じアプリ」を満たすための構成）

| 層 | 採用技術 | 補足 |
|---|---|---|
| 種別 | デスクトップアプリ（Windows想定） | Tauri v2 |
| フロントエンド | React 18 + Vite 5 | |
| 状態管理 | `useReducer` + Context | 外部状態ライブラリ不使用 |
| 永続化 | SQLite（`@tauri-apps/plugin-sql`、DBファイル `tasks.db`） | |
| 設定保存 | `@tauri-apps/plugin-store`（`config.json`） | DBパスのみ |
| UI設定保存 | ブラウザ `localStorage`（`taskmanager.*` キー） | テーマ・ペイン幅など |
| ダイアログ | `@tauri-apps/plugin-dialog` | フォルダ選択・確認・保存 |
| ファイル書込 | `@tauri-apps/plugin-fs` | レポート.txt保存 |
| ウィンドウ状態 | `@tauri-apps/plugin-window-state` | 位置・サイズ復元 |
| 自動更新 | `@tauri-apps/plugin-updater` | 署名付き（第19章、任意） |
| Excel生成 | `exceljs`（**遅延import**） | メインバンドル軽量化のため |
| D&D | HTML5標準 Drag&Drop | 追加ライブラリ不使用 |

> ドラッグ&ドロップ・状態管理・カレンダー描画は既存の重量級ライブラリに頼らず、標準機能で実装する方針。Excel生成のみ `exceljs` を使い、かつ動的import（`(await import('exceljs')).default`）で初期ロードを軽くする。

### 2.2 非機能要件

- **パフォーマンス**: 初期表示は高速。通常操作は即時にUIへ反映（楽観的更新）。不要なアニメーション・不要な通信をしない。
- **応答性**: タスク登録は「N相当の操作 → タイトル入力 → Enter」で3秒以内を目標。完了は1クリック。
- **レスポンシブ**: ノートPC（≥1024px）／タブレット・スマホ（<1024px）に対応。
- **フォント**: OS内蔵フォントのみ（追加ダウンロードなし）。本文は明朝/ゴシック、数値・等幅箇所は等幅フォント。
- **オフライン**: ネットワーク不通でも全機能が動作（更新チェックを除く）。

### 2.3 ウィンドウ

- タイトル「タスク管理」。初期サイズ 800×600、リサイズ可、フルスクリーン無効。
- OSネイティブのファイルドロップ（`dragDropEnabled`）は**無効**にする（アプリ内HTML5 DnDと競合させないため）。

## 3. データモデル

### 3.1 テーブル定義（SQLite）

すべてのIDは文字列。日付は原則ローカル暦の `'YYYY-MM-DD'` 文字列。日時（`completed_at`, `created_at`, `updated_at`）はISO文字列（`new Date().toISOString()`）。

```sql
categories (
  id TEXT PRIMARY KEY, name TEXT NOT NULL,
  sort_order INTEGER, created_at TEXT, updated_at TEXT
)

projects (
  id TEXT PRIMARY KEY, name TEXT NOT NULL, color TEXT,
  sort_order INTEGER, created_at TEXT, updated_at TEXT
)

tasks (
  id TEXT PRIMARY KEY, title TEXT NOT NULL, status TEXT NOT NULL,
  scheduled_date TEXT, completed_at TEXT,
  category_id TEXT, project_id TEXT, parent_id TEXT,
  start_date TEXT, end_date TEXT, priority TEXT,
  sort_order INTEGER, recurrence TEXT,
  created_at TEXT, updated_at TEXT,
  console_end_date TEXT     -- 予約カラム（後述、現状は未使用）
)

activities (
  id TEXT PRIMARY KEY, task_id TEXT NOT NULL, body TEXT NOT NULL,
  created_at TEXT, updated_at TEXT
)
```

### 3.2 フィールドの意味

**task**
- `status`: `'TODO'` | `'DONE'`。
- `scheduled_date`: 予定日。`null` の場合は **Inbox（日付未定）** 扱い。
- `completed_at`: 実際に完了した日時（ISO）。**月次実績集計はこれを使う**（予定日ではない）。
- `category_id` / `project_id`: 分類。任意。削除時はタスク側が `null` に戻る（FK制約は張らずアプリ側で処理）。
- `parent_id`: 親タスクID。子タスク（サブタスク）用。ルートは `null`。
- `start_date` / `end_date`: **WBS/ガント上でのみ**編集される計画期間。コンソール（カレンダー）には影響しない。
- `priority`: `'high'` | `'medium'` | `'low'` | `null`。UI上 `high` は「★（重要）」。
- `sort_order`: 同一グループ内の並び順（整数）。
- `recurrence`: 予約カラム（繰り返し機能は未実装）。

**category / project**
- `color`: 識別色（`#RRGGBB`）。`projects.color` はDB永続化される。
  - （注）`categories` テーブルには本仕様のスキーマ上 `color` カラムを含めること。UIでカテゴリ色を設定・利用するため、再現時は `categories` にも `color` を持たせ永続化する。

**activity**
- タスク単位の作業メモ（作業ログ）。`body` は複数行可。

### 3.3 予約カラム console_end_date について

`console_end_date` はスキーマ上に存在するが、**現行アプリのロジックは一切使用していない**（読み書きしない）。「WBSの計画期間をコンソールの表示帯へ明示反映する」将来機能のための予約。**再現時は必須ではない**。本仕様の機能要件はこのカラム無しで完全に満たせる。

### 3.4 初期データ

- 初回起動時（categories が空）に、カテゴリ **「開発」** を1件だけ自動生成する。
- projects / tasks / activities は空で開始。

## 4. 状態管理・永続化の要件

### 4.1 Single Source of Truth

- アプリのメモリ上の状態（`{ tasks, categories, projects, activities }`）を唯一の真実とし、DBはそれをミラーする書き込み先とする。
- 起動時に4テーブルを全SELECTして状態を復元する。
- 操作は **まず状態を即時更新（再描画）** し、**その差分を非同期でDBへ書き込む**（楽観的更新）。派生データ（カレンダー割付・WBSツリー・集計）は状態から都度算出する（メモ化）。

### 4.2 アクション一覧（状態遷移の仕様）

以下の操作を提供する。括弧内は主要な副作用。

| アクション | 効果 |
|---|---|
| タスク追加 | 新規タスクを `status='TODO'` で作成。`sort_order` は「親があれば同じ親の兄弟の末尾」「なければ同じ `scheduled_date` グループの末尾」に採番。 |
| 親＋子まとめて追加 | 親タスク＋指定タイトルの子タスク群を作成。子は親の `project_id` を継承、`parent_id=親`、`scheduled_date=null`。 |
| タスク更新 | 指定パッチをマージ、`updated_at` 更新。 |
| 完了トグル | `status` を TODO↔DONE 反転。DONEなら `completed_at=現在時刻`、TODOなら `null`。 |
| サブツリー一括完了 | 対象タスクとその全子孫を done/undone。done時 `completed_at` は既存を保持しつつ未設定なら現在時刻、undone時 `null`。 |
| 親子付け替え | `parent_id` を変更し、新しい親の兄弟末尾へ `sort_order` 採番。 |
| 期間設定 | `start_date` / `end_date` を更新（WBS用）。 |
| 予定日移動 | `scheduled_date` を指定日（または `null`＝Inbox化）へ。同日グループ末尾へ `sort_order` 再採番。 |
| 並び替え | 指定ID順に `sort_order` を 0,1,2… で振り直す。 |
| 子タスク追加 | 親の `project_id` を継承、`parent_id=親`、`scheduled_date=null` で追加。 |
| 優先度トグル | `priority` を `'high'` ↔ `null` で反転。 |
| 削除 | タスク削除。**子は削除された親の親（＝祖父、無ければルート）に再ペアレントして残す**。当該タスクの activities も削除。削除後 **Undoトースト** を表示。 |
| 復元 | 削除したタスクを元のまま復活（Undo用、同IDが既存なら無視）。 |
| カテゴリ CRUD | 追加／改名／色変更／削除。削除時、そのカテゴリを持つタスクの `category_id` を `null` に。 |
| プロジェクト CRUD | 同上。削除時 `project_id` を `null` に。 |
| アクティビティ CRUD | タスク単位メモの追加／編集／削除。 |
| インポート | 全状態を差し替え（全テーブルを消して再投入）。 |
| リセット | 全データ削除→初期状態（カテゴリ「開発」のみ）へ。 |

### 4.3 Undoトースト

- 削除時に「タスクを削除しました」＋「元に戻す」ボタンのトーストを表示。
- 表示時間 **6000ms（6秒）** で自動消滅。「元に戻す」押下で復元し、トーストを閉じる。

### 4.4 永続化の保存先

- **DBパス**: `plugin-store`（`config.json`, キー `dbPath`）。未設定なら既定 URI `sqlite:tasks.db`（＝`%APPDATA%\<app>\tasks.db`）。フォルダ指定時は `sqlite://<正規化パス>/tasks.db`（バックスラッシュをスラッシュ化）。
- **テーマ**: `localStorage['taskmanager.theme']`（`'light'`|`'dark'`）。
- **ペイン分割比**: `localStorage['taskmanager.split']`（%）。
- **WBS左列幅**: `localStorage['taskmanager.wbs.leftw']`（px）。

### 4.5 ID生成

セッション内一意なID。形式: `` `${prefix}_${Date.now().toString(36)}_${連番}_${6文字ランダム}` ``（prefix例: task=`t`, category=`c`, project=`p`, activity=`a`）。

## 5. 全体画面構成・レイアウト

### 5.1 ビュー切替（ViewToggle）

ヘッダーに「コンソール / WBS」トグルを常時置き、切替える。初期は「コンソール」。

### 5.2 ノートPC（幅 ≥1024px）: 2ペイン1画面（Dashboard）

- ヘッダー: ブランド「タスク管理」／ViewToggle／プロジェクトフィルタ／右側に `Inbox`（未処理件数バッジ付き）`Log` `設定` ボタン。
- **コンソール時**: 左ペイン=Today、右ペイン=Calendar の横並び。中央に**ドラッグ可能な区切りバー**。
  - 分割比は初期 **57.5%**、ドラッグ範囲は **25%〜72%** にクランプ、値を `localStorage` に保存。
  - ページ全体はスクロールせず、各ペインが内部スクロール。
- **WBS時**: 全幅でWBS/ガントを表示。
- `Inbox` / `Log` は右からの**スライドオーバー**、`設定` はモーダルで開く（Escで閉じる）。Inboxバッジ = `scheduled_date` なし かつ TODO の件数。

### 5.3 タブレット・スマホ（幅 <1024px）: タブ切替（Tabbed）

- 上部バー: ブランド／ViewToggle／設定ボタン。その下にプロジェクトフィルタ。
- **下部ナビ**（BottomNav）: Today / Calendar / Log / Inbox の4タブ（アイコン＋ラベル）。
  - アイコン: Today `◎` / Calendar `▦` / Log `↧` / Inbox `⌁`。
- コンソール時は選択タブの画面。Todayタブでは Today の下に Calendar も縦積み表示（区切り「Calendar」）。
- WBS時は全幅WBS（下部ナビはWBS中はどのタブも非アクティブ）。下部ナビ操作でコンソールへ戻る。

### 5.4 プロジェクトフィルタ（ProjectFilter）

- ピル型トグル。先頭「すべて」＋各プロジェクト（`sort_order` 昇順）。プロジェクト0件なら非表示。
- 選択中ピルはアクティブ表示。色付きプロジェクトはアクティブ時 `borderColor=色`, `background=色+'22'`（16進アルファ）、先頭に色ドット。
- 値（`'all'` | projectId）は全画面で共有され、Today/Calendar/Inbox/WBS の表示スコープを絞る。

## 6. デザイン言語

### 6.1 配色思想「色 = 達成の記録」

- 基調3値: **和紙 washi（地）** / **墨 sumi（文字・枠）** / **朱 shu（強調・達成）**。
- **未完了はすべて墨色**。**完了した瞬間だけ朱色（朱印）が現れる** → 「完了履歴を資産にする」思想の可視化。
- プロジェクト識別色を加える。カレンダーのタスクラベルやレーンをプロジェクト色で見分ける。
- 状態を色だけに依存させない（チェック記号・テキストも併用）。

### 6.2 表現ルール

- 見出しは明朝系、数値（カレンダー日付・集計）は等幅系。
- 情報密度は低め・余白広め・色は使いすぎない（ミニマル）。
- モーダルは極力使わず、その場でインライン完結させる。

### 6.3 ダークモード

- ライト/ダークの2テーマ。`document.documentElement.dataset.theme='dark'`（ライトは属性削除）で切替。
- 起動時に `localStorage['taskmanager.theme']` を読み、適用する。

### 6.4 カラーピッカーのプリセット（12色・順序固定）

`#C0402E, #E07040, #D4A820, #7AAF3C, #2E8A60, #2080AA, #2A52A0, #6B4CA0, #B85C8A, #7A6A5A, #404040, #909090`。
加えて任意色（`<input type=color>`）も選べる。

## 7. 共通コンポーネント要件

### 7.1 クイック追加バー（AddTaskBar）

- 先頭 `＋`、タイトル入力、「詳細」トグル、状況により「Inbox」「追加」ボタン。
- **Enterで即登録**。タイトル空のときは登録不可（追加系ボタン無効）。
- 既定日（`defaultDate`）が今日以外に設定されている場合、日付チップ「M月D日」＋「×（今日に戻す）」を表示。
- 「詳細」を開くと: 日付（`type=date`）／プロジェクト（`projects>0`のとき）／カテゴリ／優先度（なし・高・中・低）／子タスク入力。
  - 詳細を開いていないときは、プロジェクトは `defaultProjectId`（フィルタ中プロジェクト）を採用、カテゴリ・優先度は無し。
  - 子タスクを追加した状態で登録すると「親＋子まとめて追加」になる。
- 「Inbox」ボタンは `defaultDate` が非nullのときのみ表示し、日付を強制的に `null` にして登録。
- 登録後はタイトル・子タスクをクリアしフォーカス復帰（セレクト類は保持）。

### 7.2 タスクリスト（TaskList）＋タスク項目（TaskItem）

- リストは同一グループ（同一予定日、またはInbox）を前提に、HTML5 DnDで**並び替え可能**。ドロップで並びを確定し `sort_order` を振り直す。
- タスク項目の行要素:
  - グリップ（`⠿`、並び替え可能時のみ）／チェックボタン（完了で `✓`）／タイトル（クリックでインライン編集）／メタ（優先度チップ 中・低、プロジェクトチップ〈色付き〉、カテゴリチップ、日付、完了日）。
  - `showStar` 時: ★（high）/☆（それ以外）トグルで優先度 high を切替。
  - `showDateActions` 時（Inbox等）: 「今日」「明日」「日付指定」ボタンで予定日設定（日付指定は隠し `type=date` の `showPicker()`）。
  - アクティビティトグル（件数 or `≡`）でメモ欄（ActivityPanel）を開閉。
  - 削除 `✕`（→Undoトースト）。
  - ケバブメニュー `⋯`: 編集／子タスクを追加／（予定日ありなら）Inboxへ移動。
- **DnDのデータ型**: `dataTransfer` に `'application/x-task-id'` と `'text/plain'` の両方でタスクIDを入れる。受け側は前者→後者の順で読む。
- **インライン編集**: タイトル（Enter/blurで確定、空や無変更は破棄）＋日付・プロジェクト・カテゴリ（変更で即更新）。
- **子タスク（サブタスク）**: 親行に「子タスク {完了数}/{総数}」の開閉トグル。子行は完了トグル・タイトル編集・日付表示・削除を持つ。
- 完了トグルは前述のとおり単体（`toggleComplete`）で行い、親の一括完了はWBS側で `setSubtreeDone` を使う。

### 7.3 アクティビティパネル（ActivityPanel）

- タスク単位のメモ一覧（`created_at` 昇順）。各項目に日時「M/D HH:mm」（時分ゼロ埋め）・本文（改行保持）・削除。
- 本文クリックで編集（Enterで確定、Shift+Enterで改行、Escで破棄、blurで確定）。
- 下部に入力欄（自動高さ調整、Enter送信 / Shift+Enter改行）。

### 7.4 確認ダイアログ（ConfirmDialog）

- メッセージ＋詳細（改行保持）＋「キャンセル」＋実行ボタン（danger時は警告色、autoFocus）。背景クリック・Escでキャンセル。

### 7.5 Undoトースト（UndoToast）

- `{message, undo}` を表示。「元に戻す」で `undo()`＋閉じる。自動消滅は状態側タイマー（6秒）が管理。

## 8. Today画面（本日）

### 8.1 見出し・追加

- 見出し「YYYY年M月D日（曜）」（今日）。クリックでカレンダーを今日に戻す（コールバック）。
- 上部にクイック追加バー。既定日は `calendarDate ?? 今日`、フィルタ中プロジェクトを既定選択、プレースホルダ「タスクを追加（Enterで登録）」。

### 8.2 プロジェクトレーン

- **本日**（`scheduled_date === 今日`）のタスクを **プロジェクトごとのレーン** に分けて表示。
- レーン一覧: フィルタ`'all'`のとき「全プロジェクト（`sort_order`昇順）＋末尾に『未分類』レーン」。特定プロジェクト選択時はそのレーンのみ。
- 各レーン内の並び: **TODOを優先度順**（high→medium→low→無し、同値は `sort_order` 昇順）→ その後 **DONEを `completed_at` 昇順**。
  - 優先度の数値: high=0, medium=1, low=2, 無し=3。
- レーン頭: 色ドット＋レーン名＋件数（0件時は件数非表示）。空レーンは「ドロップしてプロジェクトをアサイン」。

### 8.3 レーンへのD&D（プロジェクト割当＋今日へ移動）

- タスクをレーンにドロップすると:
  1. 予定日が今日でなければ今日へ移動（`sort_order`再採番）。
  2. `project_id` を当該レーンに設定（『未分類』にドロップした場合は `null`）。

### 8.4 期限超過（overdue）callout

- 「TODO かつ `scheduled_date` あり かつ `scheduled_date < 今日`」のタスクを、`scheduled_date` 昇順で別枠表示。
- 見出し「未完了のタスク（予定日を過ぎています）」。各行に「・M月D日予定」＋「今日へ移動」ボタン（押すと今日へ移動し超過リストから外れる）。
- （注）自動で予定日を書き換えない。「いつやる予定だったか」の履歴を残すため、ユーザー操作でのみ移動する。

### 8.5 Inbox枠

- `scheduled_date` なし かつ TODO のタスク（`sort_order`昇順）を表示（`showDateActions`付き）。空なら「Inboxは空です」。
- ここへのドロップで対象タスクを `scheduled_date=null`（Inbox化）にする。

## 9. Calendar画面（カレンダー）

### 9.1 基本方針

- **平日（月〜金）のみ表示**。土日は表示しない（曜日ヘッダーは 月火水木金 の5列）。週は**月曜始まり**。
- タスクは `scheduled_date` に一致する**単一の日セル**に表示する（複数日にまたがる帯表示は行わない）。
- プロジェクトフィルタ適用（`project_id` 不一致を除外）。

### 9.2 表示モード（3種）

- **今週（week）**: 基準日を含む週の月〜金（1行5セル）。
- **2週間（twoweek）**: 当週月〜金＋翌週月〜金（2行）。
- **1か月（month）**: 月曜始まりの月グリッドから各週の月〜金だけを切り出す。月初・月末に前後月の空セル（`null`）が生じ得る。

### 9.3 レイアウトモード（2種）

- **グリッド**（`⊞`）: 5列カレンダー。各日セルに日番号・祝日名・タスクラベル群。
- **リスト**（`☰`）: 日付を縦に列挙。左に日・曜日・祝日名、右にタスクラベル群（無い日は「—」）。

### 9.4 タスクラベルの配色

- 色の決定: **プロジェクト色を優先**、無ければカテゴリ色。
- 色があり かつ未完了のとき: `backgroundColor=色+'55'`, `borderLeft=3px solid 色`。
- 色が無く未完了で優先度ありのときのみ優先度クラスを付与。完了は淡色化。

### 9.5 ナビゲーション

- `‹ / 中央ラベル / ›`。移動量: week=±7日, twoweek=±14日, month=±1か月。
- ラベル: month=「YYYY年M月」、week/twoweek=「{開始}〜{終了}」（週は+4日=金、2週は+11日）。
- 「今日」相当のリセット（外部トリガ）で表示位置を今日基準へ再設定。

### 9.6 今日・選択・祝日ハイライト

- 今日セル・選択日セルを強調。祝日は祝日名を表示（第16章の算出ルール）。

### 9.7 日付選択リスト

- 選択日の下部に、その日のタスクを「TODOを`sort_order`昇順→DONEを`completed_at`昇順」で一覧表示。空なら「この日のタスクはありません」。

### 9.8 別日へのD&D

- 日セルへドロップで `scheduled_date` を変更（同日末尾へ`sort_order`再採番）。`start_date`/`end_date`/`console_end_date` へは影響しない。

## 10. WBS / ガントチャート画面

単一プロジェクトを親子ツリーに分解し、左にツリー、右にガントを整列表示する。

### 10.1 プロジェクト選択

- フィルタが `'all'` 等でプロジェクト未確定なら、選択ピッカー（プロジェクトのピル一覧）を表示。0件なら「プロジェクトがありません。設定から追加してください。」。

### 10.2 WBSツリー構築ロジック（純粋関数）

- タスクを `parent_id`（無しは `'__root__'`）でバケツ化。兄弟は `bySort`（`sort_order`昇順、未定義は0）で整列。
- **WBS番号**: ルートは "1","2",…（1始まり）。子は親番号に `.順序` を連結（"1.1","1.1.2"…）。表示順（`sort_order`順）に基づく連番。
- **進捗ロールアップ**: 葉は `{total:1, done: DONEなら1}`。親は子孫の**葉**の合計。`親進捗 = 配下完了葉数 / 配下全葉数`。中間ノードは分母に含めない。`allDone = total>0 && done===total`。
- **葉の期間 `leafSpan`**: `start = start_date ?? scheduled_date ?? null`、`end = end_date ?? start_date ?? scheduled_date ?? null`。`start`が無ければスパン無し（バー非表示）。`end < start` は `end=start` に補正。`scheduled_date`のみのタスクは1日バー。
- **親の期間ロールアップ**: 有効な子スパンの `start=min`, `end=max`（最早開始〜最遅終了）。全子スパン無しなら親も無し。

### 10.3 左ツリーパネル

- 行高 **38px**、階層インデント **depth×15px**。左列初期幅 **340px**（最小220・最大760、`localStorage`保存、右端ハンドルでドラッグ）。
- 各行: 折りたたみキャレット（子あり時 ▸/▾）／WBS番号／チェック（葉=`toggleComplete`、親=`setSubtreeDone(!allDone)`、親は`allDone`で完了表示）／タイトル（クリックでインライン編集、Enter/blur確定・Esc破棄）。
- アクション: 「＋子」（子追加行を開く＋親を展開）／「→」インデント（直前兄弟の子にする、無ければ不可）／「←」アウトデント（祖父の子にする／祖父無しならルート化、ルートは不可）／「📅」期間ポップオーバー（**葉のみ**）／「✕」削除。
- 子追加行: 入力（Enterで連続追加・Escで閉じる・空blurで閉じる）。

### 10.4 期間設定ポップオーバー（葉のみ）

- 開始／終了の `type=date`。初期値 `start=start_date??scheduled_date`, `end=end_date`。終了が開始より前になる入力は開始に合わせて補正。「クリア」で両日null。外側クリック・Escで閉じる。

### 10.5 右ガントパネル

- ズーム: 日=34px/日、週=16px/日、月=7px/日（初期「日」）。
- **表示範囲**: 可視ノードのスパンから min/max を取り、無ければ `今日-3日〜今日+21日`。必ず今日を含めた上で、最終範囲は `min-2日 〜 max+4日`。
- 軸ヘッダー: 月帯（連続同月をまとめ「M月」）＋日セル。日番号の表示条件は 日=毎日 / 週=月曜のみ / 月=1日のみ。週末・今日に強調。
- **今日ライン**: 範囲内なら当日セル中央に縦線。
- **今日へスクロール**: ズーム変更・プロジェクト変更時に今日が中央付近へ来るよう即時スクロール。「今日」ボタンで滑らかスクロール。
- **バー**: `left = 開始からの日数×dayW`、`width = (開始〜終了の両端含む日数)×dayW`。塗り幅=進捗率%。ツールチップ「M月D日〜M月D日・{pct}%」。`終了 < 今日 かつ 未完` で overdue 表示。葉/親（leaf/summary）を区別。
- **バー操作（葉のみ）**: 本体ドラッグで平行移動（日数維持）、左右エッジで開始/終了リサイズ。移動量は `round(Δx/dayW)` 日。開始が終了を越えない／終了が開始を下回らないよう制約。確定時 `start_date`/`end_date` を更新。**親バーはドラッグ不可**（子から自動集計）。
- ヘッダーに全体進捗バー（`round(done/total×100)%`＋`(done/total)`）。
- ツールバー: 「Excel出力」（出力中/ノード0件で無効、ラベル「出力中…」）／「今日」／ズーム（日・週・月）。
- ルートタスク追加バー（プレースホルダ「ルートタスクを追加（Enterで登録）」）。

> 注: 「日程を更新／コンソールに反映」ボタンは**現行版に存在しない**。WBSでの日付編集は `start_date`/`end_date` のみを更新し、`scheduled_date` は変えない。

## 11. Excel出力（WBS帳票）

`exceljs` を遅延importして `.xlsx` を生成する。画面の配色思想（墨/朱/和紙）を帳票へ移植し、**条件付き書式でガント帯を動的描画**する（日付・進捗を編集するとバーが追従）。

### 11.1 全体構成

- 対象ノード: ツリーを**折りたたみ無視で全件展開**。
- 左固定表側8列（A〜H）: No / タスク名 / カテゴリ / 開始 / 終了 / 日数 / 進捗 / 完了。幅 8/42/14/12/12/7/9/9。
- 日付列: 表側の右隣（1-indexedで列9=I）から、範囲 `min-2日〜max+2日`（**画面と違い後方は+2日**）の各日を1列（幅2.8）。
- ウィンドウ枠固定: 左8列・上5行。グリッド線非表示。
- タイトル帯（行1〜3）: 行1=プロジェクト名（16pt太字）、行2=「全体進捗 {pct}% ({done}/{total})  出力日 {today}」、行3=スペーサ。
- ヘッダー（行4上・行5下）: 表側は縦結合ヘッダー、日付側は行4=月帯「M月」、行5=日番号（`numFmt='d'`、今日/週末で色分け）。
- データ行（行6〜）: 各ノード1行。No（等幅・淡墨）／タスク名（親は太字、`indent=depth+1`）／カテゴリ名／開始・終了（`yyyy/m/d`）／日数（`diffDays+1`）／進捗（`0%`書式、100%で朱太字）／完了（`done/total`）。

### 11.2 色（ARGB, 先頭FF=不透明）

`paper=FFFBFAF6, paperSink=FFEEECE4, ink=FF21201B, inkSoft=FF6C675C, inkFaint=FFA7A294, rule=FFE3DFD4, ruleStrong=FFD3CEC0, shu=FFC0402E, shuLight=FFE29A8B, trackLeaf=FFE7E3D9, trackSummary=FFCDC7B8`。本文フォント Yu Gothic、数値系 Consolas。

### 11.3 条件付き書式（バー描画）

各データ行の日付列レンジに、その列のヘッダー日付 `hdr`（行5固定）と、開始 `s`（$D）・終了 `e`（$E）・進捗 `p`（$G）・親葉フラグ（隠し列、親=1/葉=0）を用いた数式ルールを適用。
- `doneThru = s + ROUND(p*(e-s+1),0) - 1`（達成分の最終日）。
- 優先度1: `AND(s<>"", hdr>=s, hdr<=doneThru)` → 朱（`shu`）で塗る（達成分）。
- 優先度2: `AND(s<>"", flag=1, hdr>doneThru, hdr<=e)` → 濃トラック（親の残り）。
- 優先度3: `AND(s<>"", flag=0, hdr>doneThru, hdr<=e)` → 淡トラック（葉の残り）。
- 親葉フラグ列は隠し（hidden, width=3）。

### 11.4 日付シリアル化・ダウンロード

- ExcelJSはUTC基準でシリアル化しTZ補正しないため、日付は **UTC深夜**（`new Date(Date.UTC(y,m-1,d))`）で生成し前日化を防ぐ。
- シート名はExcel禁止文字（`\ / ? * [ ] :`）を空白化し最大31文字。空なら「WBS」。
- ファイル名 `{シート名}_WBS_{today}.xlsx`。Blob→`createObjectURL`→`<a download>`クリック→1秒後にURL解放。失敗時は alert「Excel出力に失敗しました。時間をおいて再度お試しください。」。

## 12. Log画面（月次ログ）

### 12.1 対象月・ナビ

- 初期は今月。`‹ / 「YYYY年M月」 / ›` で前後月移動。

### 12.2 集計の厳密な定義（`today`基準）

- **完了 `completed`**: `completed_at` が対象年月（ローカル時刻）に属するタスク。
- **未完了 `incomplete`**: `status==='TODO'` かつ `scheduled_date` が対象年月に属する。
- **翌月繰越 `carryover`**: `incomplete` のうち `scheduled_date < today`（期限超過）。
- **完了数** = `completed.length`、**未完了数** = `incomplete.length`、**翌月繰越** = `carryover.length`。
- **完了率**: `denom = 完了数 + 未完了数`。`denom===0` なら「—」、それ以外は `round(完了数/denom×100)%`。

### 12.3 表示

- サマリー4カード: 完了タスク／未完了／翌月繰越／完了率。
- **カテゴリ別完了数**: `completed` を `category_id`（無しは「（カテゴリなし）」、削除済みは「（削除済み）」）で集計し**件数降順**。1件以上のとき表示。
- **完了履歴**: `completed` を**完了日**（`completed_at`のローカル日付）でグルーピング。日付降順、日内は `completed_at` 降順。見出し「M月D日（曜）」、各行 `✓`＋タイトル＋カテゴリチップ。0件なら「この月に完了したタスクはありません」。

### 12.4 「今月やったことをコピー」

- 完了0件で無効。クリップボードへ以下を書き込む（`completed_at`昇順）:
```
■ {YYYY年M月}に行ったこと

・{タイトル}
・{タイトル}
...
```
- `navigator.clipboard` 不可時は隠しtextarea＋`execCommand('copy')`、それも不可なら `window.prompt`。成功後ボタンを「コピーしました」に2秒間切替。

### 12.5 「月次レポートを書き出し (.txt)」

- 完了0かつ未完了0で無効。区切り線は「━」×28。構成:
```
■ {YYYY年M月} 月次レポート
出力日: {YYYY年M月D日（曜）}

━━…（28）
サマリー
━━…
完了タスク    {n}件
未完了タスク  {n}件
翌月繰越      {n}件
完了率        {n}% または —

（カテゴリ別完了数：1件以上のとき）
━━…
カテゴリ別完了数
━━…
  {name}  {n}件

━━…
完了履歴
━━…
（日付昇順。各日）
{M月D日（曜）}
  ✓ {title}{ [カテゴリ名]}
（無ければ「  （なし）」）

（未完了：1件以上のとき）
━━…
未完了タスク（月内予定）
━━…
  □ {title}{ [カテゴリ名]}{  {M月D日}}{  ※翌月繰越}
```
- 保存: `save()` ダイアログ（既定名 `{YYYY}{MM}_月次レポート.txt`、拡張子txt）→ 選択されれば `writeTextFile`。

## 16. 日付・祝日ロジック（厳密仕様）

### 16.1 日付ユーティリティ

- 日付文字列はローカル暦 `'YYYY-MM-DD'`。曜日配列 `['日','月','火','水','木','金','土']`。
- `todayStr()`=本日。`addDays(str,n)`=n日加算。`diffDays(a,b)=round((b−a)/86400000)`（DST安全）。`minDate/maxDate`=ISO辞書順（空は他方）。
- `formatFullJP`=「YYYY年M月D日（曜）」、`formatMonthDayJP`=「M月D日」、`monthLabel`=「YYYY年M月」。
- `addMonth({year,month},d)`: `idx=year*12+(month-1)+d` → `{year:floor(idx/12), month:(idx%12)+1}`。
- `weekStart(str)`: 月曜始まり（`diff=(getDay()+6)%7` 分戻す）。
- `monthGrid`: 月曜始まり、先頭 `firstCol=(1日getDay()+6)%7` 個の`null`＋日付＋末尾7の倍数まで`null`。

### 16.2 日本の祝日 `getJapaneseHolidays(year)`（Map<日付, 名称>）

- **固定**: 1/1元日, 2/11建国記念の日, 2/23天皇誕生日, 4/29昭和の日, 5/3憲法記念日, 5/4みどりの日, 5/5こどもの日, 8/11山の日, 11/3文化の日, 11/23勤労感謝の日。
- **春分の日**（3月）: `floor(20.8431 + 0.242194*(y-1980) - floor((y-1980)/4))`。
- **秋分の日**（9月）: `floor(23.2488 + 0.242194*(y-1980) - floor((y-1980)/4))`。
- **ハッピーマンデー**: 成人の日=1月第2月曜, 海の日=7月第3月曜, 敬老の日=9月第3月曜, スポーツの日=10月第2月曜。第n・指定曜日は `day = 1 + ((dow−firstDow+7)%7) + (n−1)*7`。
- **国民の休日**: 秋分の日 − 敬老の日 がちょうど2日なら、その間日（敬老の日+1）を「国民の休日」。
- **振替休日**: 日曜に当たる祝日は、翌日以降で祝日/既定振替でない最初の平日を「振替休日」にする（連続祝日を飛ばす）。

- 配布は GitHub Releases ＋ 署名付き updater（`latest.json`）。タグ push で自動ビルド・署名・リリース。
- **セキュリティ要件**: 更新署名の秘密鍵は絶対にリポジトリへコミットしない（`.gitignore`）。鍵はCI Secretsから供給。

## 18. 実装スコープ

### 18.1 実装する（MVP＋現行機能）

Today / Calendar / WBS・ガント / Excel出力 / Log / Inbox、タスクCRUD・完了・並び替え・D&D、子タスク（親子・カスケード完了）、アクティビティ（作業メモ）、優先度（★）、プロジェクト／カテゴリ管理、予定日と完了日時の分離、月次集計・「今月やったこと」コピー・レポート出力、Undo削除、DBパス変更、ダーク/ライト、祝日表示。

### 18.2 実装しない

チーム共有・権限・コメント・添付・チャット・複雑なタグ・AI自動スケジューリング・高度分析ダッシュボード・外部招待。**繰り返しタスク（`recurrence`）と全文検索・網羅的ショートカットは現状未実装**（データ列 `recurrence` は保持）。

### 18.3 既知の設計メモ（再現時の判断材料）

- **予定と実績の分離**: 予定日超過でも自動で日付を変えない（履歴保持）。実績集計は必ず `completed_at` を用いる。
- **カレンダーは平日のみ・単日表示**（帯展開なし）。WBS側のみ `start_date`/`end_date` の期間バーを持つ。両者の日付は独立し、WBS編集はカレンダーに波及しない。
- **DB同期は非同期の fire-and-forget**。新規作成系はID/日時が確定してから状態とDBの双方へ入るよう実装すること（状態とDBのID食い違いを防ぐ）。

## 19. 用語集

- **コンソール**: Today＋Calendarの実行ビュー。
- **WBS**: Work Breakdown Structure。プロジェクトの親子分解。
- **葉／親**: 子を持たない末端タスク／子を持つ集約タスク。
- **Inbox**: 予定日未定タスクの一時保管（`scheduled_date=null`）。
- **今日の3つ / ★**: 重要タスク。現行は優先度 `high`（★）で表現。

## 20. 受け入れ基準チェックリスト（再現評価用）

### データ・状態
- [ ] SQLite（またはローカルDB）に4テーブル相当を保持し、起動時に全復元する。
- [ ] 初回起動でカテゴリ「開発」が自動生成される。
- [ ] 予定日 `scheduled_date` と完了日時 `completed_at` を別管理する。
- [ ] 削除時に子タスクが祖父へ再ペアレントされ、activitiesも消える。
- [ ] 削除に6秒のUndoトーストが付く。

### コンソール
- [ ] PCで Today＋Calendar が2ペイン、区切りドラッグで比率変更（25–72%）できる。
- [ ] Todayがプロジェクトレーン＋未分類レーンで表示され、TODO優先度順→DONE完了時刻順に並ぶ。
- [ ] レーンへのD&Dでプロジェクト割当＋今日へ移動が同時に起きる。
- [ ] 期限超過（TODO かつ `scheduled_date<今日`）が別枠に出て「今日へ移動」できる。
- [ ] Calendarが平日のみ、週/2週/月＋グリッド/リストで表示される。
- [ ] Calendarでラベルがプロジェクト色優先で着色され、別日D&Dで予定日変更できる。
- [ ] 日本の祝日が正しく算出・表示される（春分/秋分/ハッピーマンデー/振替/国民の休日）。

### WBS・Excel
- [ ] 親子ツリーとWBS番号（1, 1.1, 1.1.2…）を表示する。
- [ ] 進捗が葉の完了で親へロールアップする（完了葉/全葉）。
- [ ] 葉バーをドラッグ移動・エッジリサイズでき、親バーは子から自動集計される。
- [ ] 日/週/月ズーム・今日ライン・今日へスクロールが動く。
- [ ] Excel出力が条件付き書式でガント帯を描画し、達成分が朱で塗られる。

### Log
- [ ] 完了数/未完了数/翌月繰越/完了率が定義どおり算出される。
- [ ] 完了履歴が `completed_at` の日でグルーピングされる。
- [ ] 「今月やったこと」コピーと月次レポート.txt出力が仕様の書式で出る。

### 設定・全体
- [ ] プロジェクト/カテゴリのCRUD（色付き）ができ、削除でタスクのFKがnull化する。
- [ ] DBファイルの保存先を変更できる。
- [ ] ライト/ダークが切替・永続化される。
- [ ] レスポンシブ（PC 2ペイン / モバイル 下部タブ）で破綻しない。
- [ ] 全体として「未完了=墨、完了=朱」のデザイン思想が貫かれている。
